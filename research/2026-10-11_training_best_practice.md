## Per-question findings

### 1. Repetition/degeneration loops
- **Greedy decoding causes self-reinforcing loops** — "The probability of a repeated phrase increases with each repetition, creating a positive feedback loop." ([Holtzman et al., arXiv 1904.09751](https://arxiv.org/abs/1904.09751)).
- **Nougat's detection is logit-variance based, not edit-distance** (the brief's assumption was wrong): variance of max logits over a sliding window B=15, threshold 6.75 (real-time: last 200 tokens, half threshold); early stop only saves compute — the collapse fix "is left for future work" ([arXiv 2308.13418](https://arxiv.org/abs/2308.13418)).
- **Nougat's augmentation is the only measured training-side fix:** random token replacement in targets up to 10% of tokens → 32% fewer failed conversions, no performance drop (same paper).
- **Loop reports are common and rarely "fixed":** Donut issue #203 (open; reporter's fix was a package downgrade), InternVL #1241 "Generation repetition after MPO post-training" (no confirmed fix), Qwen2-VL #1954 "repeating and not ending", #1611 "Infinite repetition bug still exists" ([donut#203](https://github.com/clovaai/donut/issues/203), [InternVL#1241](https://github.com/OpenGVLab/InternVL/issues/1241), [Qwen2-VL issues](https://github.com/QwenLM/Qwen2-VL/issues)).
- **Label smoothing: no anti-repetition evidence** — improves BLEU despite worse NLL, says nothing about repetition ([arXiv 1906.02629](https://arxiv.org/abs/1906.02629)). Exposure bias/scheduled sampling citation: [arXiv 1506.03099](https://arxiv.org/abs/1506.03099).
- **Your EOS handling is correct** — verified in code: `train_lora.py:73` keeps the closing `<|im_end|>` in labels, ruling out the "model never learnt to stop because EOS was masked" cause.

### 2. Official fine-tune hyperparameters (InternVL / Qwen2-VL)
- **Official InternVL2.5-1B LoRA script** (verified today, raw file): lr **4e-5**, **1 epoch**, total batch **16**, cosine, warmup **0.03**, wd 0.01, seq 8192, `max_dynamic_patch 6`, `freeze_llm/mlp/backbone True`, `use_llm_lora 16` — **your topology is identical; your lr is 2.5× theirs and you run 2 epochs vs 1** ([script](https://raw.githubusercontent.com/OpenGVLab/InternVL/main/internvl_chat/shell/internvl2.5/2nd_finetune/internvl2_5_1b_dynamic_res_2nd_finetune_lora.sh)).
- **Official InternVL3-1B script is full-FT only** (no official 1B LoRA script exists): lr **1e-5**, batch **128**, 1 epoch, trains **LM + projector (MLP)**, freezes only ViT ([script](https://raw.githubusercontent.com/OpenGVLab/InternVL/main/internvl_chat/shell/internvl3.0/2nd_finetune/internvl3_1b_dynamic_res_2nd_finetune_full.sh)).
- **Qwen2-VL official LoRA**: r8/α16, dropout 0, suggested lr **1e-6–2e-7** (million-sample SFT context, not 1K-page task adaptation), 3 epochs, `tune_mm_mlp False` ([README](https://raw.githubusercontent.com/QwenLM/Qwen2-VL/main/qwen-vl-finetune/README.md)). LLaMA-Factory's current VL LoRA example: lr **1e-4**, 3 epochs, rank 8 ([yaml](https://raw.githubusercontent.com/hiyouga/LLaMA-Factory/main/examples/train_lora/qwen3vl_lora_sft.yaml)). "LoRA Learns Less and Forgets Less": LoRA ≈ 10× full-FT lr ([arXiv 2405.09673](https://arxiv.org/abs/2405.09673)).
- **Verdict: 176 steps is not obviously too little** — official scripts run 1 epoch with save_steps 200 and no doc states a step minimum; with loss already at 0.22 *and* loops on training pages, the binding problem is generation degeneration, not undertraining.

### 3. Constrained decoding with transformers 4.57
- **lm-format-enforcer is the fit** — verified API: `JsonSchemaParser(pydantic_schema)` + `build_transformers_prefix_allowed_tokens_fn(tokenizer, parser)` → `generate(prefix_allowed_tokens_fn=...)`; has an official image→JSON VLM notebook ([repo](https://github.com/noamgat/lm-format-enforcer), [notebook](https://github.com/noamgat/lm-format-enforcer/blob/main/samples/colab_llama32_vision_enforcer.ipynb)).
- **outlines v1** wraps generation (`outlines.Generator(outlines.from_transformers(...))`), examples are CausalLM; InternVL compat unverified ([github.com/dottxt-ai/outlines](https://github.com/dottxt-ai/outlines)). **xgrammar** is engine-first (vLLM/SGLang/TRT-LLM); HF use is a DIY bitmask LogitsProcessor; paper claims "up to 100x speedup over existing solutions" — over other *constraint engines*, in engine co-design ([repo](https://github.com/mlc-ai/xgrammar), [arXiv 2411.15100](https://arxiv.org/abs/2411.15100)). **transformers-cfg**: EBNF `GrammarConstrainedLogitsProcessor` ([repo](https://github.com/epfl-dlab/transformers-CFG)).
- **transformers 4.57 has no native support** — v4.57.0 release notes instead *removed* constrained beam search ([release](https://github.com/huggingface/transformers/releases/tag/v4.57.0)).
- **Accuracy evidence: none that constraints improve field accuracy.** Grammar-Aligned Decoding shows constraints can distort the model distribution → "grammatical but… low-quality" ([arXiv 2405.21047](https://arxiv.org/abs/2405.21047)); Koo et al. claim correctness/speed of the machinery, not accuracy gains ([arXiv 2407.08103](https://arxiv.org/abs/2407.08103)); OpenAI's "100% vs <40%" is schema-following reliability with models *trained* for constraints ([OpenAI blog](https://openai.com/index/introducing-structured-outputs-in-the-api/)). Treat as validity guarantee; check field-F1 after enabling.

### 4. Evaluation practice
- **Donut's metric is the protocol to copy:** per-field F1 ("Even if a single character is missed, the score assumes the field extraction is failed") + TED accuracy = max(0, 1 − TED(pred, gt)/TED(∅, gt)); malformed output = fields treated as lost, parsed with "simple regular expressions" ([arXiv 2111.15664](https://arxiv.org/abs/2111.15664)). Nougat uses normalized character edit distance ([arXiv 2308.13418](https://arxiv.org/abs/2308.13418)).
- **Early stopping plumbing:** `load_best_model_at_end` + `metric_for_best_model` + `EarlyStoppingCallback` ([HF callbacks docs](https://huggingface.co/docs/transformers/main_classes/callbacks)).
- **Scale:** DocVQA v1.0 val = 5,349 pages; the field convention is hundreds-to-thousands held-out. Your 5% split (~70 pages) plus the 254-page verified gold set are the right pools; **10 training pages is the current blind spot** (DocVQA split: [arXiv 2007.00395](https://arxiv.org/abs/2007.00395)).

### 5. Target format
- **Donut chose JSON, not XML** (brief premise corrected): "We adopt a JSON format due to its high representation capacity", with field names as special tokens invertible to JSON ([arXiv 2111.15664](https://arxiv.org/abs/2111.15664)).
- **TOON:** vendor claims "~46.3% fewer tokens" ([toon-spec](https://github.com/toon-spec/toon)); independent paper: "TOON yields markedly more compact outputs… but lower structural correctness when models lack native support" ([arXiv 2601.12014](https://arxiv.org/abs/2601.12014)). YAML evidence is blog-tier only.
- **Minified vs pretty, fixed key order, schema-in-prompt: no measured studies found.** Closest anchors: RFC 8785 canonical JSON ([rfc-editor](https://www.rfc-editor.org/rfc/rfc8785)) and the train/serve *consistency* rule, which you already satisfy. Long homogeneous lists are the documented loop-risk pattern ([1904.09751](https://arxiv.org/abs/1904.09751)).

### 6. Training data practice
- **Overfit-a-tiny-subset gate** is canonical ("verify you can overfit a tiny subset of the dataset") ([karpathy.github.io](https://karpathy.github.io/2019/04/25/recipe/)) — your `smoke_e8` run is this gate.
- **Packing:** TRL explicitly does not support packing for vision datasets; at your ~4k-token sequences it's unnecessary ([TRL docs](https://huggingface.co/docs/trl/sft_trainer)).
- **Teacher-label noise: no quantified effect found** for ~1% wrong values in SFT — don't expect a measurable win from mitigation (see unsourced list).
- **Synthetic documents carry doc-parsing training** in Donut/SynthDoG ("synthetic images were enough for the document IE task"), Nougat, Pix2Struct ([2111.15664](https://arxiv.org/abs/2111.15664), [2210.03347](https://arxiv.org/abs/2210.03347)).
- **Epochs:** "training with up to 4 epochs of repeated data yields negligible changes to loss" vs unique data — pretraining regime, SFT transfer unverified ([arXiv 2305.16264](https://arxiv.org/abs/2305.16264)).

### 7. Gaps in your setup
- **NEFTune** — one flag; claims up to 30–60% AlpacaEval; unproven for extraction ([2310.05914](https://arxiv.org/abs/2310.05914)).
- **Projector training** — the standard next lever for a new image domain; official full-FT trains it ([InternVL3 script](https://raw.githubusercontent.com/OpenGVLab/InternVL/main/internvl_chat/shell/internvl3.0/2nd_finetune/internvl3_1b_dynamic_res_2nd_finetune_full.sh)).
- **SFT→GRPO/DPO** — recipes exist (HF cookbook, VLM-R1 for InternVL/Qwen-VL) but no published doc-JSON F1 win ([cookbook](https://huggingface.co/learn/cookbook/en/fine_tuning_vlm_grpo_trl), [VLM-R1](https://github.com/om-ai-lab/VLM-R1)); closest prior art to your exact task is an AWS doc-to-JSON SFT write-up ([AWS blog](https://aws.amazon.com/blogs/machine-learning/fine-tune-vlms-for-multipage-document-to-json-with-sagemaker-ai-and-swift)).
- **Closest prior art to your exact task** is an AWS doc-to-JSON SFT write-up (same URL, directly above).

- That `repetition_penalty` fixes fine-tuned VLM loops — folklore only; direct counter-evidence for JSON in your own ngram runs and vLLM's default of 1.0.
