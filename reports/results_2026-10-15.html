CV page image to ATS JSON with models under 1B parameters

Three small vision-language models are fine-tuned to read a photo or scan of one CV page and write its content as JSON in a fixed schema. The labels come from the GLM-5.3-Flash teacher model.

All scores are on the development sets: 50 human-reviewed gold pages and 79 teacher-labelled validation pages. The 204-page test set has not been scored. Three runs are still running; their results are not in this report.

Best model per student

Lenient field F1 ignores case, spacing and punctuation; any letter or digit difference is an error. Content F1 also accepts correct text that was split, merged or placed under a nearby field. The epoch of each run is chosen on the validation pages.

Key-by-key generation

Instead of writing the whole JSON in one answer, the model is called once per key (29 keys). The code writes the JSON up to "key":, including the values already generated for earlier keys, and the model writes only that key's value, quotes and brackets included, or null when the page has none. Training uses the existing teacher labels, with 8 random keys per page per epoch.

  • More training closes most of the gap: every run was still rising at its last epoch.
  • From the best weights after 3 epochs, content F1 is the same as whole-page on gold (0.842 vs 0.839): the model reads the same text; the remaining loss is wording and field placement.
  • Invalid values and values cut at the token limit are rare (1–4 per set for InternVL).
  • Cost: 29 generation calls per page instead of 1.
  • Running: 6 epochs from the best InternVL weights. Adopted only if it beats 0.728 / 0.732 by more than 0.02 on both sets.

Running now

  • InternVL: key-by-key, 6 epochs from the best weights (decides adoption).
  • SmolVLM: current recipe trained on 2,465 pages (993 extra pages) instead of 1,472, aimed at field-placement errors. Compared with the same seed without them, 0.645 / 0.656.
